## 5. Schema decisions

- Canonical concept names come **verbatim** from `final_field_comparison.csv` so this table is a strict superset of the field-comparison work.
- `in_scope` = `false` is used for fields that exist in the source but are out of scope for the supervisor's site/facility ask (e.g. contact fields, non-site metadata). Nothing is removed; the flag lets the supervisor toggle inclusion in the HTML.
- `data_type = definition` marks the field whose value is a definition of the concept (rather than a data value). Per-RI rules for its content are in §8.

## 6. Field allowlist — explicit, not keyword-based

Table B is built from an **explicit allowlist** of field paths.

The allowlist is itself a reviewed artifact: `outputs/site_terms_field_allowlist.csv`, one row per (`ri`, `field_path`, `in_allowlist` bool, `notes`). It is populated in **Step 1** (enumerate all field paths seen in the cached data for the 20 sites, then decide in/out per field) and reviewed before Step 3.

Why allowlist, not keyword denylist: a keyword test on field names misses prose in fields whose names don't contain "description" / "summary" / "abstract". An allowlist only includes what was deliberately reviewed.

Second guard: **`max_value_length = 80` characters.** Any value in Table B longer than 80 chars is rejected at build time (raises). This catches accidental inclusion of long prose that slipped past the allowlist.

## 7. What is excluded

- **DEIMS free text** — summary, abstract, description, any narrative field. Never committed. Also never committed: site-manager names and emails from the detail records.
- **Raw polygon WKT / vertex coordinates** — local-only, never committed (PM 2026-11-11). Derived numbers only (area, boundary yes/no).
- **ICOS and ACTRIS free text** — excluded from committed tables. **This is a precaution, not a licence finding** — it is not a statement about their licence. The licence status for ICOS and ACTRIS is stated in §9 and in each table header.
- **Any value longer than 80 characters** — rejected at build time.

## 8. Definition column per RI

The `definition` column in Table A is populated per RI:

| RI | Content |
|---|---|
| DEIMS | `[FLAGGED: pending licence provenance - EnvThes scheme: http://vocabs.lter-europe.net/EnvThes/]` (same marker as #17) |
| EnvThes | same marker (this is the source for eLTER site-description terms) |
| ACTRIS | Actual text from `ACTRIS_vocabulary.ttl` (CC0 1.0, confirmed) |
| ICOS | Actual text, with per-row licence note: *"ontology CC0 (cc:license, ICOS ERIC 2024); per-concept licence not stated; ICOS licence page not verified by us"* |

## 9. Per-RI licence handling

Every committed table header cites the per-RI licence state:

- **DEIMS:** `DEIMS-SDR, CC BY-NC 4.0, https://deims.org/terms` — this feeds the **open supervisor decision** on how the thesis cites DEIMS. PM flagged it as a legal question they cannot decide.
- **ACTRIS:** `CC0 1.0 (confirmed, scheme file + TTL)`
- **ICOS:** `ontology CC0 (cc:license, ICOS ERIC 2024); per-concept licence not stated; ICOS licence page not verified by us`
- **EnvThes:** `CC BY 4.0 per scheme file; LICENSE file 404; third-party source tags (Henderson's / GEMET / NCIT) require provenance checks`
